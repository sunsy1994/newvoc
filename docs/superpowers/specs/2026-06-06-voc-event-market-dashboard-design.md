# VOC看事件：市场看板设计

## 目标

`VOC看事件 / 市场看板` 是第一个面向业务的真实看板，服务市场部视角。它不展示原始底表，也不展示缺少来源的样例数据，而是基于事件、主贴、评论、作者、KOL画像等已入库资产，回答一个事件的传播规模、变化节奏、渠道来源、KOL参与情况和热门内容表现。

第一版先做一个页面，其他二级菜单暂时不展开。所有内容都收敛在市场看板中，后续如果某个区域复杂到需要独立工作流，再拆成新的二级菜单。

## 页面原则

- 只展示真实数据：页面指标必须来自 PostgreSQL 底表、ETL聚合或明确接口返回，不使用 mock 数据。
- 缺字段不硬凑：如果某个图表缺少必要字段，接口返回空数组或缺失说明，前端展示空状态，不编造结论。
- 卡片式布局：整体延续 macOS / Linear / Notion 风格，浅灰背景、低对比度、圆角卡片、轻微阴影。
- 图表清新克制：颜色轻、留白足，重点突出趋势和结构，不做重装饰。
- 先看态势，再下钻：首屏展示核心判断，热门帖子支持点击查看详情，但榜单本身保持轻量。
- AI摘要后置：第一版不做AI摘要。后续单独设计 agent，明确输入、输出、证据约束和防幻觉规则。

## 页面结构

### 1. 事件筛选卡

位置：页面顶部。

功能：
- 支持选择事件。
- 当前第一版可能只有一个事件，但组件必须按多事件设计。
- 选择事件后刷新整页看板数据。

展示字段：
- 事件名称
- 品牌
- 车型
- 事件类型
- 事件状态
- 事件周期

数据来源：
- 事件资产表或事件列表接口。

必要字段：
- `event_id`
- `event_name`
- `brand_name`
- `model_name`
- `event_type`
- `event_status`
- `start_time`
- `end_time`

### 2. 声量总览卡组

位置：事件筛选卡下方，横向卡片组。

指标：
- 总声量
- 主贴数
- 评论数
- KOL发声
- 总互动量

口径：
- 总声量 = 主贴数 + 评论数。
- 主贴数 = 当前事件下主贴数量。
- 评论数 = 当前事件下评论数量。
- KOL发声主指标 = 参与发声的去重KOL人数。
- KOL发声辅助指标 = KOL贡献的主贴数。
- 总互动量 = 直接汇总主贴底表中的总互动量字段，不重新计算点赞、评论、收藏、分享。

展示建议：
- `KOL发声` 卡片主数值显示 `N 位KOL`。
- 卡片辅助文案显示 `贡献 M 条主贴`。
- 总互动量使用千分位格式。

### 3. 声量趋势折线图

位置：中部主图卡片。

目的：
- 判断事件在发布时间维度上的爆发、爬升、回落。

口径：
- 时间字段使用发布时间，不使用采集时间或入库时间。
- 按日聚合。
- 主贴声量 = 当日主贴数。
- 评论声量 = 当日评论数。
- 总声量 = 当日主贴数 + 当日评论数。

图表形式：
- 折线图。
- 三条线：主贴声量、评论声量、总声量。
- 总声量可以使用稍深颜色，主贴和评论使用更浅的辅助颜色。

必要字段：
- 主贴发布时间。
- 评论发布时间。
- `event_id` 或可通过内容关联到事件。

### 4. 渠道分布堆积柱状图

位置：中部或下部大卡片。

目的：
- 判断事件传播和讨论主要来自哪些平台。

口径：
- X轴为渠道。
- Y轴为声量。
- 堆积拆分为主贴数和评论数。
- 评论渠道优先继承所属主贴渠道。

图表形式：
- 堆积柱状图。
- 主贴和评论使用同色系不同深浅，保证清新且可读。

必要字段：
- 主贴渠道。
- 主贴ID。
- 评论所属主贴ID。

### 5. KOL类型分布

位置：右侧或下部中型卡片。

目的：
- 判断这个事件吸引了哪些类型的KOL参与。

口径：
- 仅统计当前事件中有发声的KOL。
- KOL类型来自KOL画像表，不在页面临时判断。
- 指标可同时返回 KOL人数、主贴数、总互动量；第一版图表主展示 KOL人数。

图表形式：
- 第一版建议横向条形图，比环形图更适合类型较多的枚举。
- 类型较多时按KOL人数倒序，只展示前若干类，其余可合并为“其他”。

必要字段：
- 主贴作者ID。
- KOL资产或KOL画像关联ID。
- `kol_main_type`。

### 6. 热门帖子榜

位置：与KOL类型分布并列或位于页面底部。

目的：
- 快速看到本事件中最值得复盘的内容。

展示字段：
- TOP序号。
- 帖子名称。
- 总互动量。

口径：
- 按主贴底表中的总互动量倒序。
- 第一版展示 Top 5 或 Top 10。
- 榜单本体保持轻量，不展示作者、渠道、发布时间等更多字段。
- 点击帖子后进入详情下钻。

下钻详情第一版范围：
- 帖子标题。
- 作者昵称。
- 渠道。
- 发布时间。
- 总互动量。
- 原文链接。
- 评论列表入口或评论列表预览。

## 接口设计

### 事件列表

`GET /api/voc/events`

用途：
- 支撑事件筛选。

返回：
- `events`

事件字段：
- `event_id`
- `event_name`
- `brand_name`
- `model_name`
- `event_type`
- `event_status`
- `start_time`
- `end_time`

### 市场看板

`GET /api/voc/events/{event_id}/market-dashboard`

用途：
- 一次性返回市场看板所需数据，保证同一页面口径一致。

返回结构：

```json
{
  "event": {},
  "overview_metrics": {},
  "volume_trend": [],
  "channel_distribution": [],
  "kol_type_distribution": [],
  "hot_posts": []
}
```

`overview_metrics`：
- `total_volume`
- `content_count`
- `comment_count`
- `kol_count`
- `kol_content_count`
- `total_engagement`

`volume_trend`：
- `date`
- `content_count`
- `comment_count`
- `total_volume`

`channel_distribution`：
- `channel`
- `content_count`
- `comment_count`
- `total_volume`

`kol_type_distribution`：
- `kol_main_type`
- `kol_count`
- `content_count`
- `total_engagement`

`hot_posts`：
- `content_id`
- `title`
- `total_engagement`

## 数据支持检查

第一版开发前需要确认以下字段是否存在或可由现有表关联得到：

- 事件表：事件ID、事件名称、品牌、车型、事件类型、状态、开始时间、结束时间。
- 主贴表：事件ID、主贴ID、标题、发布时间、渠道、作者ID、总互动量、原文链接。
- 评论表：评论ID、主贴ID、事件ID或可关联事件、评论发布时间。
- 作者/KOL关系：主贴作者是否能关联到KOL资产。
- KOL画像表：KOL ID、KOL主类型 `kol_main_type`。

如果某个区域缺少字段：
- 缺趋势字段：隐藏趋势图或展示“缺少发布时间字段”。
- 缺渠道字段：隐藏渠道分布或展示“缺少渠道字段”。
- 缺KOL画像字段：隐藏KOL类型分布或展示“尚未维护KOL画像”。
- 缺总互动量字段：热门榜单不展示，不改用临时计算口径。

## 前端实现边界

- 当前只保留 `VOC看事件 / 市场看板` 一个二级菜单。
- 原 `传播内容`、`KOL与用户` 二级菜单先从导航中移除或不显示。
- 页面使用卡片式布局，不使用原始底表组件。
- 图表使用轻量清新的配色。
- 不引入复杂状态管理。
- 事件选择可以通过URL参数保存，例如 `/voc/events/market?event_id=...`。
