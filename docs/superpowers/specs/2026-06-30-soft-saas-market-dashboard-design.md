# Soft SaaS 全局框架与市场看板升级设计

## 目标

在不改变数据接口、业务逻辑和现有交互能力的前提下，升级 AutoVOC 的全局框架与市场看板。视觉参考 Dribbble 常见的 Soft SaaS Dashboard，但优先保证企业业务系统的清晰度、可读性和操作效率。

成功标准：

- 全局框架与市场看板形成统一、可复用的视觉语言。
- 现有导航、事件筛选、主题切换、图表提示、详情弹窗和数据状态继续可用。
- 市场看板仍按“结论—证据—图表”的故事线组织，而不是拆成松散图表集合。
- 桌面端保持高信息密度；窄屏不溢出，关键操作仍可达。
- TypeScript 类型检查通过，改动不触及后端与其他业务页面逻辑。

## 范围

本阶段只修改：

1. 全局应用框架：页面背景、双栏导航、内容容器、导航状态与基础视觉令牌。
2. 市场看板：标题区、事件筛选、指标概览、AI 总结和现有故事卡片。
3. 与上述界面直接相关的共享样式与组件。

本阶段不修改产品看板、销售看板、资产库、任务流程、系统设置的页面内部布局，也不修改任何后端接口和数据结构。

## 视觉方向

采用“克制的 Soft SaaS”方案：

- 暖灰白页面底色搭配白色内容表面，减少大面积高饱和色。
- 主色使用低饱和青绿色，辅以蓝、紫、橙作为数据语义色。
- 通过细边框、轻层次阴影和 12–20px 圆角建立柔和质感；避免厚重玻璃效果和装饰性渐变。
- 标题紧凑明确，正文与数字对比清晰；表单与导航的焦点、悬停、选中状态保持可辨识。
- 动效只用于状态反馈，时间短且支持 `prefers-reduced-motion`。

## 信息架构与组件

### 全局框架

- 保留现有“双层导航”信息架构，避免重新学习路径。
- 一级导航承担业务域切换，二级导航展示当前业务域页面。
- 内容区使用统一最大宽度、稳定边距与柔和页面底色；大屏不无限拉宽，窄屏允许导航和内容合理收缩。
- 品牌区、导航项和活动状态使用同一套尺寸、圆角和颜色令牌。

### 市场看板页头

- 左侧展示页面名称和用途说明，右侧保留事件选择、查看按钮与主题选择。
- 事件元数据收拢为紧凑标签组，减少与主要操作争抢注意力。
- 空数据时仍显示页头和筛选，正文提供明确的导入与 ETL 提示。

### 指标与故事模块

- 五个核心指标保持同层展示，突出数值、弱化装饰图标。
- AI 总结作为整页结论入口，视觉层级高于单个故事卡，但不使用强烈渐变抢占内容。
- 声量节奏、讨论主体、平台扩散、区域响应、话题传播和评论质量继续沿现有顺序构成故事线。
- 每张故事卡统一采用：结论标题、关键证据、紧凑图表或排行、必要操作。
- 同一论点的证据保持在一张卡内，不额外拆分小卡片。

## 交互与状态

- 事件选择和“查看”按钮继续通过现有查询参数刷新数据。
- 主题切换保留，但默认 Soft 主题与全局框架协调；下拉菜单支持点击选择、清晰焦点和选中态。
- 所有已有详情弹窗、图表悬停、排行点击和 AI 总结入口保持原行为。
- 明确覆盖加载、空数据、接口失败和长文本场景；不得用假数据掩盖失败。
- 交互控件具有键盘焦点样式，颜色对比不依赖阴影单独表达状态。

## 实现边界

- 优先调整现有 CSS 变量和组件 class，不引入新的 UI 框架。
- 继续使用 Tailwind CSS、Lucide 图标和当前组件结构。
- 只在重复且稳定的视觉模式确实需要时提取小型共享组件，不为一次升级建立新抽象层。
- 不改动服务端取数函数、接口路径、类型定义和故事卡业务计算。
- 保留工作区中与本任务无关的现有修改，不纳入提交。

## 验证

1. 运行 `npm run typecheck`，确认 TypeScript 无错误。
2. 对市场看板执行桌面与窄屏视觉检查，验证无横向溢出、裁切和间距异常。
3. 手动验证一级/二级导航、事件筛选、主题切换、详情交互和空数据状态。
4. 对比升级前后页面，确认信息与功能均未丢失，仅视觉层级和布局发生目标内变化。
5. 检查 `prefers-reduced-motion`、键盘焦点和主要文本对比度。
