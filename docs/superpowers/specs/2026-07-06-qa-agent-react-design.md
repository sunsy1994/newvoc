# 事件问答 Agent（ReAct）设计说明

## 目标

在现有 `app/agents`、统一 dispatcher、事件看板服务和运行时 AI 配置之上，新增独立 `qa` Agent。它回答“为什么、意味着什么、证据在哪里”类问题，通过受约束工具查询真实数据，并在最多三轮 ReAct 中根据新增证据修正上一轮草稿。

## 核心约束

- 所有事实和数字必须来自 Python 工具结果；模型不得生成工具结果中不存在的数字。
- ReAct 最多三轮。每轮包含：选择工具、执行工具、读取观察结果、修订上一轮回答、判断是否继续。
- 每次回答必须明确展示事件名称、统计区间和数据口径。
- 请求接收时间按 `Asia/Shanghai` 记录为用户提问时间。
- 用户明确指定时间时使用其时间范围。
- 未指定时间且属于跨事件问题时，默认范围为提问时间向前 30 天（含当天）。
- 用户指定具体事件时，默认使用该事件完整周期；回答中明确标注事件起止时间。
- 证据不足时明确说明缺少什么，不用常识补全业务事实。

## 能力边界

第一版支持以下问答方向：

- 市场：传播爆发原因、声量节奏、平台质量、传播主体、话题、地域与评论质量。
- 产品：关注点、正负向原因、机会优先级、PKO 对象与胜负证据。
- 销售：销售意向、购买信号、线索来源、重点内容与建议跟进用户。
- 跨事件：近 30 天事件规模、指标排行和异常对比。

第一版不执行自由 SQL、不访问未注册工具、不生成报告、不主动修改任何业务数据。

## 包结构

```text
app/agents/qa/
├── __init__.py
├── graph.py
├── state.py
├── prompts.py
├── parser.py
└── tools.py
```

- `state.py`：问答状态、轮次、时间范围、事件上下文、工具观察和答案草稿。
- `prompts.py`：工具选择、草稿修订和最终校验提示词。
- `parser.py`：运行时模型调用、严格 JSON 校验、历史消息规范化。
- `tools.py`：工具注册表、事件解析、时间范围和现有看板服务适配。
- `graph.py`：LangGraph 节点、三轮限制、条件路由和公共 runner。

## 工具目录

所有工具接收结构化参数，并返回统一 envelope：`tool_name`、`event`、`time_scope`、`data_scope`、`facts`、`evidence`、`notes`。

第一版注册：

- `list_events`：按时间范围和品牌列出事件。
- `get_market_story`：获取市场规模、节奏、平台、主体、话题、地域和评论质量。
- `get_product_story`：获取产品关注点、机会优先级、PKO 和评论证据。
- `get_sales_story`：获取销售漏斗、购买信号、来源、内容和用户线索。
- `get_discussion_evidence`：按事件与产品关注点获取原始评论证据。

工具只包装现有 `event_voc_insights` 与 `home_dashboard` 服务，不复制 SQL。

## ReAct 三轮

### 初始化

规范化历史消息、记录 `asked_at`、解析显式时间、解析 `event_id/event_name`。若事件不明确且问题必须绑定事件，则进入澄清。

### 每轮

1. `decide`：模型根据问题、旧草稿、已有观察选择一个已注册工具，或声明证据已经充分。
2. `validate_action`：Python 校验工具名称、参数、事件和时间范围。
3. `execute_tool`：执行确定性工具并追加观察结果。
4. `revise`：模型只使用全部观察结果修订上一轮草稿，返回答案、证据充分性、缺口和下一步建议。
5. `route`：充分则结束；不充分且轮次少于三轮则继续；达到三轮后强制最终校验。

最终校验由 Python 检查事件名称、统计区间、数据口径是否出现；缺失时附加标准口径说明。回答响应不暴露内部工具名、数据库字段或 LangGraph 轨迹。

## API 与 dispatcher

- 在 `AGENT_RUNNERS` 注册 `qa`。
- 继续使用 `POST /api/agents/run`，请求：`capability="qa"`、`message`、可选 `event_id`、`history`。
- runner 返回：`status`、`answer`、`suggested_questions`、`requires_clarification`、`event_name`、`time_scope`、`data_scope`。
- 原 `/api/agents/data-question/run` 和现有问数 Agent 保持不变。

## 前端

- 首页选择“问答”时调用 `/api/agents/run`，传入 `capability="qa"`。
- “问数”继续调用现有 data-question 契约。
- 对话区展示 Agent 返回的事件名称、时间范围和数据口径；不显示内部执行轨迹。
- 报告和洞察入口在对应 Agent 完成前保持“即将接入”状态，不再错误发送给问数 Agent。

## 错误处理

- 缺少事件：返回澄清问题及候选事件名称。
- 工具无数据：保留已获得证据，明确说明当前数据不足。
- 模型返回非法工具或 JSON：拒绝执行并返回可理解错误。
- 单轮工具失败：记录观察错误；仍可根据已有证据修订，三轮后结束。
- 模型或数据库异常沿用现有 API 的 400、502、503、504 映射。

## 验证

- 测试默认近 30 天范围、显式时间覆盖和指定事件完整周期。
- 测试最多三轮、每轮基于上一轮草稿修订、非法工具拒绝和证据不足结束。
- 测试市场、产品、销售工具只返回现有服务数据。
- 测试 dispatcher 注册与 `/api/agents/run` 契约。
- 测试首页问答入口使用 `qa`，问数入口保持原路径，报告/洞察不误发。
