# 竞品动态报告 Agent 设计

## 1. 目标

在现有 AI 报告入口中增加“竞品动态报告”，与“事件报告”并列为两个明确能力。竞品报告根据用户对话中的品牌和时间范围查询竞品库，选出 Top3 作品，融合人工维护的视频解读，并生成固定模板的长 HTML 报告。

第一版追求在线可用和规则稳定，不引入 Deck、PPT 或 PDF 链路。

## 2. 已确认的业务规则

- AI 报告入口只提供“事件报告”和“竞品动态报告”，不做两者之间的语义猜测路由。
- 用户未指定品牌时，系统明确提示“未指定品牌，将默认使用上汽大众”，并按上汽大众查询。
- 用户未指定时间时，默认查询近一个月，并在对话回复和报告中明确展示实际时间范围。
- 用户指定自然语言时间时，由 LLM 提取候选范围，再由确定性代码校验和规范化。
- Top3 必须在品牌和时间过滤之后计算。
- 总互动量口径固定为：点赞数 + 评论数 + 收藏数 + 分享数。
- 视频解读为一条作品一份 Markdown，由用户在竞品作品库中直接编辑维护，不提供文件上传。
- Top3 有视频解读时融合展示；没有时对应内容显示“无”，不得生成或猜测缺失信息。
- 报告生成后进入报告资产，并在 AI 对话中返回可点击的查看卡片。

## 3. 范围

### 第一版包含

- 竞品作品的视频解读维护。
- 品牌与时间范围解析。
- 竞品作品和账号数据查询。
- 确定性 Top3 排名与指标计算。
- 固定结构的长 HTML 报告。
- 报告资产存储、列表与查看。
- AI 对话内生成状态和报告链接。

### 第一版不包含

- Deck HTML。
- PPT 或 PDF 导出。
- Markdown 文件上传与批量解析。
- 多品牌横向综合报告。
- 自动生成缺失的视频描述。
- 让 LLM 自行选择 Top3 或计算业务指标。

## 4. 数据设计

新增独立的作品解读表，不修改采集作品的原始事实字段。

建议字段：

| 字段 | 说明 |
| --- | --- |
| `work_id` | 关联竞品作品，唯一键 |
| `insight_markdown` | 用户直接维护的视频及评论解读 |
| `updated_at` | 最近更新时间 |
| `updated_by` | 可选，记录维护人 |

作品被删除时，解读资料不参与任何指标计算。是否级联删除遵循现有数据资产约束；第一版优先保留资料并在查询时通过作品表关联。

报告资产沿用现有报告资产能力，增加报告类型 `competitor_report`，保存品牌、起止时间、生成时间、HTML 内容或可访问地址，以及生成时使用的作品证据标识。

## 5. 竞品作品库交互

竞品作品列表的操作列增加“维护解读”。点击后打开轻量编辑弹窗：

- 显示作品标题、作者、品牌和发布时间，帮助确认对象。
- 提供 Markdown 多行编辑区。
- 支持保存、更新和清空。
- 列表用简短状态标识“已维护 / 未维护”。
- 不增加上传、预览器或版本管理。

## 6. Agent 与 LangGraph 流程

竞品报告使用独立的 `CompetitorReportGraph`，不复用事件报告的数据采集节点。

```text
接收竞品报告请求
  → 解析品牌与时间候选值
  → 规范化并确认最终查询范围
  → 查询竞品作品与账号数据
  → 确定性计算指标和 Top3
  → 按 work_id 查询 Top3 解读资料
  → LLM 基于结构化数据和证据生成结论
  → 固定模板渲染长 HTML
  → 保存报告资产
  → 返回对话报告卡片
```

### LLM 负责

- 理解用户表达的品牌和时间。
- 基于工具返回的数据归纳 3 至 5 条核心发现。
- 解释 Top3 为什么获得互动，但必须引用作品事实或人工维护资料。
- 组织符合固定章节结构的文本。

### 确定性代码负责

- 默认品牌和默认时间。
- 日期范围校验。
- 数据库过滤和查询。
- 互动量计算、排序和 Top3 选择。
- 数据缺失判断。
- HTML 转义、模板渲染、资产保存。

## 7. 报告固定结构

在线报告沿用新版 Skill 的长报告方向，精简为适合系统查看的模块：

1. 报告标题、品牌和数据时间范围。
2. 本期概览：作品数、账号数、总互动量、平均互动量。
3. 核心发现：3 至 5 条有数字或明确案例支撑的结论。
4. Top3 热门作品：原始作品事实、互动指标、主题判断和视频解读。
5. 账号互动贡献。
6. 发布时间与互动走势。
7. 原始话题与主题分布。
8. 经销商承接效果；证据不足时只陈述账号表现。
9. 数据口径和证据说明。

Top3 解读区按照 Skill 规则组织为“视频基本信息 / 视频内容解析 / 评论解析”。评论解析顺序为“评论情绪 / 评论关键词 / 典型评论 / 作者回复”。缺失项显示“无”。

不在系统报告中展示 Skill 路径、Python 脚本名、数据库字段名等实现信息。

## 8. Skill 在线化方式

`E:\openclaw实战bak\新skill` 作为设计与规则来源，不作为生产运行时外部依赖。

接入时只迁移在线报告需要的内容：

- 输入字段映射与数据口径。
- 标签体系。
- 长报告章节规则。
- 长 HTML 的模板和必要渲染逻辑。

不迁移 Deck、PDF、Excel 命令行包装器和示例输出。AutoVOC 直接从数据库构造标准化数据对象，避免先导出 Excel 再读取。

## 9. 异常与降级

- 查询范围没有作品：不生成空报告，回复该品牌在该时间范围暂无竞品数据。
- 作品不足三条：按实际数量生成 TopN，并明确样本数量。
- Top3 没有维护解读：展示作品事实，解读字段显示“无”。
- 缺账号类型：不推断官方或经销商身份。
- 缺评论资料：不生成评论情绪、关键词和典型评论。
- LLM 生成失败：保留确定性统计结果，报告任务标记失败并允许重新生成，不保存伪完成资产。

## 10. 验收标准

1. 在竞品作品库可直接创建、修改和清空单条作品解读。
2. 未指定品牌时明确提示默认上汽大众，最终报告品牌正确。
3. 未指定时间时使用近一个月，并在回复和报告中展示具体起止日期。
4. 指定时间后只使用该范围内的数据。
5. Top3 与相同筛选范围下按统一互动量口径排序的结果一致。
6. Top3 解读严格按 `work_id` 匹配；未维护内容显示“无”。
7. 报告不出现数据库字段名、内部 Tool 名或 Skill 文件路径。
8. 报告成功后出现在报告资产列表，并能从对话卡片点击查看。
9. 系统中没有 Deck 和 PDF 的入口或生成选项。
10. 事件报告现有流程保持不变。
