# 产品 AI 报告图表优化设计

日期：2026-07-26  
分支：`codex/lieflat-ai-report-visuals`

## 目标

在不修改现有业务接口、不生成演示数据、不重构其他看板的前提下，优化产品 AI 报告的图表模式：

1. 扩大 AI 报告弹窗，缓解标题、标签和图形堆叠。
2. 将图表标题、副标题和 AI 解读统一放在图形上方。
3. 将产品 PKO 关系图改为 L6 `The contributor field` 的多个产品点簇。
4. 将产品点正负反馈改为 L15 `What they fear, tick by tick` 的 100% tick 构成图。

## 范围

### 本轮修改

- 部门 AI 报告弹窗尺寸与图表模式排版。
- 产品报告的 `product-sentiment` 图。
- 产品报告的 `product-pko-evidence` 图。
- 新增 L6、L15 两种系统色 SVG 模板及其运行时数据校验。
- 与上述改动直接相关的后端契约、前端类型、缓存校验和测试。

### 本轮不修改

- 市场报告的 `用户反馈构成` 情感占比图。
- 销售报告和事件综合报告的固定故事线。
- 产品报告的其他三张图。
- AI 提示词的业务判断逻辑。
- 底层 PKO 证据查询和数据库结构。

## 方案选择

采用定点替换方案：

- `product-sentiment`：F6 替换为 L15。
- `product-pko-evidence`：L12 替换为 L6。
- 其余产品图表顺序保持不变。

不同时保留旧图，避免重复结论和报告过长；不整体重排产品报告，控制本轮影响范围。

## 弹窗与信息层级

- 弹窗宽度使用约 `94vw`，最大宽度约 `1480px`。
- 最大高度使用约 `92vh`，内部保持独立滚动。
- 小屏继续使用安全边距和 `w-full`，不得产生横向页面滚动。
- 图表卡片信息顺序固定为：
  1. 标题；
  2. 副标题与指标口径；
  3. AI 图表解读；
  4. SVG 图形或明确空状态；
  5. 数据来源。
- L6 图表在双列图表网格中横跨两列；其他图表保持现有响应式网格。

## L6 用户反馈构成

### 业务语义

- 一张宽图展示多个产品点簇。
- 每个产品点是一个中心节点。
- 产品点周围的气泡是与该产品点发生真实 PKO 对比的车系。
- 每个车系气泡的面积与该车系在该产品点上的真实对比评论次数成比例。

### 数据来源

继续使用现有 `pko.evidence_comments`：

- `dimension`：产品点；
- `target`：对比车系；
- 每一条可渲染记录：一次真实对比；
- `comment_id`、`comment_text`、`result_bucket`：继续保留作为证据和可访问文本。

不增加新的数据库查询，不让 LLM 生成节点、次数或车系名称。

### 聚合和排序

- 按 `dimension + target` 聚合对比次数。
- 产品点按总对比次数降序排列；相同次数使用产品点名称稳定排序。
- 同一产品点内的车系按对比次数降序排列；相同次数使用车系名称稳定排序。
- 使用当前报告上下文中已有的全部可渲染产品点，不人为只选最高频产品点。
- 如果数据量超出 SVG 可读范围，沿用现有后端确定性证据上限；不得使用随机抽样。

### 面积编码

- 气泡面积与次数成比例。
- 半径按 `sqrt(count / maxCount)` 换算，并设置仅用于可读性的最小和最大半径。
- 中心产品点节点不编码对比次数，必须与车系气泡在形态和标签上明确区分。
- 标签至少显示车系名称和对比次数；长名称使用安全截断，并保留完整可访问文本。

### 交互与证据

- 有真实记录的车系气泡支持键盘聚焦和鼠标悬停。
- 聚焦后显示产品点、车系、对比次数及代表性真实评论。
- 原始证据行继续保存在 chart data 中；L6 只改变可视化聚合，不丢失证据。
- 数据依据模式继续使用现有证据引用与计算口径。

### 空状态

没有同时具备产品点和对比车系的真实记录时：

- 保留固定 L6 卡片；
- 显示明确空状态原因；
- 不渲染演示节点；
- 不采用 LLM 图表解读作为事实判断。

## L15 产品点正负反馈

### 业务语义

- 每个产品点一行。
- 每行固定表示 100% 用户反馈。
- 行内依次编码正向、中性、负向三类占比。
- 图例和副标题明确说明一格对应的百分点，以及三种状态的颜色含义。

### 数据来源与计算

继续使用现有 `product_focus.aspects`：

- 产品点名称使用现有 aspect/name/label 字段。
- 正向占比使用现有 `positive_rate`。
- 负向占比使用现有 `negative_rate`。
- 中性占比计算为 `100 - positive_rate - negative_rate`。

该中性值是由现有两个比例确定性计算的剩余量，不属于 LLM 推断。

### 异常处理

- 只接受有限非负数值。
- 正向率和负向率均限制在 0–100 的业务范围。
- 因历史数据或舍入造成合计略超 100 时，按比例确定性归一化到 100。
- 缺失正向率或负向率的产品点不进入图形，并保留明确空状态。
- 不把缺失值视为 0，不生成演示占比。

### tick 编码

- 每行使用固定数量的 tick，视觉总长恒为 100%。
- tick 分配采用确定性最大余数法，保证各段 tick 数之和等于总 tick 数。
- 系统主色表达正向，系统负向色表达负向，中性使用主题灰阶。
- 文本同时显示精确百分比，tick 只承担快速比较。

## 模板与兼容性

- 后端模板白名单新增 `L6`、`L15`。
- 前端 `ReportTemplateId`、registry 和运行时缓存校验同步新增这两个模板。
- 新生成产品报告固定顺序保持五张：
  1. `product-focus`；
  2. `product-sentiment`（L15）；
  3. `product-opportunity`；
  4. `product-pko-evidence`（L6）；
  5. `product-pko-matrix`。
- 历史已保存的 F6、L12 产品报告继续由现有 registry 渲染，不能因模板升级失效。
- 新模板不引入 ECharts、Chart.js、CDN、`dangerouslySetInnerHTML` 或 `eval`。

## AI 边界

- LLM 仍只提供受限的图表解读文本。
- LLM 不提供产品点、车系、次数、百分比、颜色、节点位置或图表类型。
- AI 解读在图形上方展示。
- 图表无可渲染数据时，不显示 LLM 推断性解读。

## 验证标准

### 后端

- L6 只接受真实且完整的 PKO 记录。
- L6 聚合、排序和次数稳定可复现。
- L15 正、中、负合计为 100%。
- 异常比例、缺失值和空数据均有确定性行为。
- 新报告使用 L6、L15；旧缓存 F6、L12 仍可恢复。

### 前端

- 弹窗达到目标宽高且小屏无横向溢出。
- 标题、副标题、AI 解读位于 SVG 上方。
- L6 横跨两列，多产品点簇标签无明显重叠。
- 气泡面积使用平方根半径换算。
- L15 tick 总数固定且颜色、图例、精确数值一致。
- L6 可键盘聚焦，SVG 有可访问名称和隐藏证据列表。
- 两个模板空状态不显示演示数据。

### 回归

- 运行相关后端测试、前端 SSR 行为测试、TypeScript 类型检查和生产构建。
- 运行外部图表运行时安全扫描。
- 对新弹窗在真实产品报告上进行视觉检查；若受运行环境阻塞，记录准确原因，不伪称通过。

## 成功标准

用户打开产品 AI 报告图表模式时：

- 弹窗空间明显增大，文字不再挤压图形；
- 图表解读先于图形被阅读；
- 用户能同时看清多个产品点分别与哪些车系发生对比，以及对比次数；
- 用户能逐产品点看清正向、中性、负向构成；
- 所有视觉数值都可追溯到现有接口数据和确定性计算。
