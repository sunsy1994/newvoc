# 竞品报告 Skill 同源渲染设计

## 目标

系统中的“竞品动态报告”必须与最终版 `weekly-voc-report` skill 的
`generate_brand_reports.py --style mckinsey` 输出保持同一结构、视觉和数据口径。
不再维护独立的简化 HTML 模板。

最终 skill 来源固定为：

- `E:\openclaw实战bak\新skill\SKILL.md`
- `E:\openclaw实战bak\新skill\scripts\generate_brand_reports.py`
- `E:\openclaw实战bak\新skill\assets\default_long_report_style.html`
- `E:\openclaw实战bak\新skill\references\input-schema.md`
- `E:\openclaw实战bak\新skill\references\label-taxonomy.md`
- `E:\openclaw实战bak\新skill\references\report-sections.md`

运行时不得依赖上述绝对路径。所需生成逻辑、样式和分类规则必须固化进项目，
保证 Windows、本地 Docker 和 Linux 部署结果一致。

## 已确认问题

### 模板偏离

当前项目模板 `app/agents/competitor_report/templates/long_report.html`
是 5,833 字节的独立简化实现；最终 skill 模板为 21,660 字节，两者哈希不同。
当前实现缺少或弱化了 skill 已有的 ECharts 图表、Top3 案例结构、热门话题、
主题分布、经销商承接和桑基图。

### 日期范围错误

通用时间解析器只识别了“5月”，未识别“5月最后一周”，因此 2026 年 5 月请求
被保存为 `2026-05-01` 至 `2026-05-31`。候选范围校验又要求 LLM 结果必须与
确定性解析一致，导致正确的最后一周候选被丢弃。

## 架构

### 同源生成器

在 `app/agents/competitor_report/` 内维护可导入的报告生成模块。其 HTML、CSS、
ECharts option、主题分类、指标计算和模块顺序来自最终 skill 的
`generate_brand_reports.py`。

生成器提供两个入口：

1. records/DataFrame 入口：供系统 Agent 直接调用。
2. Excel 入口：保留 skill 原有离线能力，便于与样例文件做一致性验证。

两个入口最终调用同一个 `build_html`，不能分别维护两套模板。

### 数据适配

Agent 工具查询 PostgreSQL 后，将数据映射为 skill 字段：

- 标题
- 作者
- 品牌
- 账号类型
- 是否官方号
- 发布时间
- 视频链接
- 互动点赞数
- 评论数
- 收藏数
- 分享数
- 总互动量
- 是否置顶
- 话题标签
- 封面图路径（存在时）

总互动量固定为点赞、评论、收藏、分享之和。数据库已有的可信总互动值仅用于
一致性校验，不能改变 skill 口径。

### Top3 视频补充

竞品库中维护的 `insight_markdown` 作为 Top3 视频补充数据，字段顺序固定为：

1. 视频介绍
2. 要点总结
3. 评论情绪
4. 评论关键词
5. 典型评论
6. 作者回复

没有维护内容时显示“无”，不得由 LLM 编造。补充内容融合进原 Top3 卡片，
不新增独立模块。

### LLM 边界

LLM 只负责：

- 3 至 5 条核心发现
- 案例意义
- 账号、节奏和经销商摘要

程序负责：

- 日期范围
- 数据筛选
- Top3 排名
- 指标计算
- 图表数据
- 主题规则分类
- HTML 渲染

LLM 不得输出 HTML、ECharts 数据或数值型图表配置。

## 固定报告结构

`mckinsey` 长 HTML 必须包含：

1. 封面与报告范围
2. 本周概览 KPI
3. 核心发现
4. Top3 热门作品
5. 账号互动贡献
6. 发布时间与互动走势
7. 原始话题与热门话题
8. 主题分类分布
9. 重点经销商承接效果
10. 官方发起到经销商承接桑基图
11. 数据口径与缺失说明

视觉、响应式行为和 ECharts option 以最终 skill 的 `mckinsey` 输出为准。

## 日期解析

新增确定性表达式：

- `YYYY年M月最后一周`
- `M月最后一周`
- `YYYY年M月最后一星期`
- `M月最后一星期`

“最后一周”定义为该月最后一个自然周的周一至周日，并裁剪到该月边界。
例如 2026 年 5 月最后一周为 `2026-05-25` 至 `2026-05-31`。

年份缺失时，沿用现有命名月份规则：月份不晚于提问月份则取当年，否则取上一年。
该确定性结果必须优先于普通“某月”解析，并允许通过 scope 安全校验。

## 错误与降级

- 查询范围无数据：返回 `no_data`，不生成伪报告。
- 缺评论数据：保留结构并说明缺失，不生成情绪结论。
- 缺视频维护内容：Top3 对应字段显示“无”。
- 缺官方/经销商关系证据：桑基图保留空态说明，不伪造连接。
- ECharts 运行资源必须随项目可用；不得因无法访问公共 CDN 造成空图。
- 报告生成失败：保存失败状态与明确错误，不将半成品写成 completed。

## 测试与验收

### 日期

- `生成2026年5月最后一周的竞品动态报告` → `2026-05-25` 至 `2026-05-31`
- `生成5月最后一周的竞品动态报告`（提问日 2026-07-28）→ 同上
- `生成5月报告` → 仍为 `2026-05-01` 至 `2026-05-31`
- 默认无时间 → 仍为近 30 天，并明确告知用户

### 生成器

- Excel 与 records 输入在同一数据集上产生相同 KPI、Top3 和图表数据。
- HTML 包含全部固定模块、ECharts 初始化和桑基图配置。
- HTML 不包含未替换占位符。
- 缺失可选数据时只出现规定空态。

### 集成

- AI 报告入口可生成最后一周竞品报告。
- 回复中的时间范围与数据库保存范围一致。
- 报告资产可打开完整 HTML。
- 现有事件报告、部门 AI 总结和报告资产不回归。

### 视觉

使用最终 skill 样例与系统生成结果做同视口对照。验收重点是结构、间距、颜色、
卡片、表格、Top3 和图表布局一致；动态数据长度允许带来自然高度差异。
