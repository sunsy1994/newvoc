# 竞品报告话题传播网络升级设计

## 目标

把竞品报告从多个并列、重复的话题维度，收敛成一条清晰故事线：

1. 发生了什么：报告概览。
2. 什么内容最值得关注：Top3 热门作品。
3. 谁贡献了主要声量：账号互动贡献 Tick Rows。
4. 传播在何时发生：发布时间与互动走势。
5. 谁在扩散哪些话题：Top10 话题—全部相关账号 Big Force。
6. 官方动作如何被承接：官方—话题—经销商 Big Threads。

本次只调整固定 HTML 报告模板和确定性数据加工，不增加 LLM 的选图、计算或布局责任。

## 报告结构调整

### 保留

- 报告概览
- 核心发现
- Top3 热门作品
- 账号互动贡献 Tick Rows
- 发布时间与互动走势
- 官方—话题—经销商 Big Threads

### 替换

“热门话题热度分布”普通横向柱图替换为 Lieflat `templates/big-force.html` 的全宽 Force Graph。

### 删除或合并

- 删除独立的“话题分类分布”表格。它与热门话题重复，且算法分类粒度较粗。
- 删除“上周该品牌相关热门话题”证据表格，把完整宽度留给传播网络。
- “重点经销商承接效果”不再作为独立面板，压缩为 Big Threads 旁的三条摘要：
  - 最强承接账号
  - 覆盖话题最多账号
  - 低效承接账号

## Big Force 数据编码

### 节点

- 大节点：累计互动量最高的 Top10 热门话题。
- 小节点：参与 Top10 话题传播的全部账号，不按全局排名截断。
- 话题节点大小：该话题累计互动量。
- 账号节点大小：该账号在 Top10 话题下所有相关作品的累计互动量。
- 账号节点颜色：官方号、经销商、其他账号。
- 话题节点使用报告主色系，与账号节点保持明显层级差异。
- 同一账号只创建一个节点；发布多个热门话题时，同时连接多个话题节点。
- 话题和账号采用独立尺寸区间，保证话题始终明显大于账号，同时保留账号间的互动差异。

累计互动量沿用现有口径：

`点赞数 + 评论数 + 收藏数 + 分享数`

### 连线

- 一条边表示某账号发布过包含该话题的作品。
- 连线粗细表示账号围绕该话题发布的作品数。
- 连线不重复编码互动量，避免与节点大小产生含义冲突。

### 筛选规则

1. 从报告时间范围内的数据提取原始话题标签。
2. 按话题累计互动量选 Top10。
3. 保留参与 Top10 话题的全部账号。
4. 同一账号只出现一次，可以连接多个话题。
5. 没有原始话题标签的数据不凭空生成关系。

## 交互

- 悬停话题：突出该话题、相关账号和连线。
- 悬停账号：突出该账号参与的全部话题。
- Tooltip 展示：
  - 节点名称
  - 节点类型
  - 累计互动量
  - 作品数
  - 互动占比
- 支持拖拽、缩放和平移。
- 点击图表空白区域恢复全局视图。
- 报告继续内嵌本地 ECharts 源码，不使用 CDN。

## 布局

话题—账号 Force Graph 使用完整报告宽度，桌面报告中最小高度为 620px。报告不再保留独立热门话题证据表格。

Big Threads 区域使用主图加摘要结构：

- 主图展示官方—话题—经销商路径。
- 摘要区只展示三个确定性结果，不重复完整经销商列表。

## 空数据与边界

- 无话题标签：显示“当前时间范围暂无可构建的话题传播网络”，不绘制模拟节点。
- 只有一个话题或一个账号：仍可正常渲染，不补造节点。
- 账号或话题名称过长：画布标签截断，Tooltip 展示完整名称。
- 累计互动量全部为零：节点采用最小尺寸，并明确显示互动量为零。
- 输入文本通过现有 JSON 与 HTML 安全处理，不使用未转义的 `innerHTML`。

## 验收标准

- Big Force 使用现有报告时间范围内的真实作品数据。
- 话题和账号节点大小均以累计互动量为主。
- 连线粗细只表示作品数。
- 最多展示 10 个话题，并展示与这些话题相关的全部账号。
- 账号类型颜色和图例清晰可辨。
- 悬停聚焦、拖拽、缩放、空白恢复均可用。
- 删除“话题分类分布”独立表格。
- 删除“上周该品牌相关热门话题”证据表格。
- 经销商摘要压缩为三条并与 Big Threads 同区呈现。
- 历史报告不迁移；重新生成的报告使用新模板。
- 竞品报告测试、全量后端测试、前端类型检查和生产构建全部通过。
