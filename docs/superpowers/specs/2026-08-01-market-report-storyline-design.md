# 市场部 AI 报告传播复盘设计

## 目标与定位

市场部 AI 报告定位为事件结束后的传播复盘，核心回答四个问题：传播结果如何、什么内容驱动传播、谁放大了传播、哪个渠道更有效。

报告只使用市场看板现有结构化数据。LLM 负责生成有层次的复盘文案，系统负责固定图表、指标计算和字段映射。报告不生成营销建议，不把产品评价或销售意向作为独立主章节。

## 故事线

### 顶部结论

用一句标题和一段摘要概括本次事件的传播模式。摘要按“结果—原因—路径—效率”组织，不逐项复述下方章节。

### 第一章：传播结果与节奏

回答事件形成了多大传播规模、何时出现峰值、峰值是否集中以及是否存在二次传播。

- 核心数据：`scale.total_volume`、`scale.content_count`、`scale.comment_count`、`scale.total_engagement`
- 节奏判断：`rhythm.rhythm_type`、`rhythm.active_days`、`rhythm.peak_date`、`rhythm.peak_volume`、`rhythm.peak_volume_rate`、`rhythm.has_secondary_peak`、`rhythm.secondary_peak_count`
- 趋势数据：`volume_trend[].date/content_count/comment_count/total_volume`

### 第二章：话题驱动

回答哪些话题带动了内容生产、用户讨论和累计互动。主结论优先识别头部话题及话题集中程度，不把提及量直接解释为态度。

- 核心数据：`hot_topics.summary`
- 明细数据：`hot_topics.topics`
- 内容证据：`evidence.hot_posts`

### 第三章：传播主体

回答哪些作者和 KOL 类型放大了传播，以及传播贡献是否集中在少数主体。

- 主体判断：`kol_and_authors.summary`
- 作者明细：`kol_and_authors.top_authors`
- 类型分布：`kol_and_authors.kol_type_distribution`

### 第四章：渠道效率

回答各平台分别依靠传播规模还是单内容效率取得贡献，避免只按照声量判断平台价值。

- 平台判断：`platform.summary`
- 平台明细：`platform.platform_efficiency`

### 复盘收束

最后用一段话总结本次事件属于何种传播模式，并串联峰值、话题、主体和平台证据。只陈述数据支持的事实与判断，不输出行动建议。

## 摘要模式

摘要模式复用产品部已确认的视觉结构和单一主题色体系，但内容结构独立：

1. 顶部核心判断区展示标题、事件名、统计周期和传播规模。
2. 纵向依次展示“传播结果与节奏—话题驱动—传播主体—渠道效率”。
3. 每章只展示一个主结论、两至三个关键指标和一段解释。
4. 详细指标与依据默认折叠，可由用户展开。
5. 数据不足时显示明确的缺失状态，不由 LLM 补齐。

## 图表模式

图表模式的说明文字位于对应图表上方。图表类型由系统固定，LLM 不选择图表，也不生成数据点。

### 传播态势：按日堆叠柱状图

- X 轴：日期。
- 堆叠序列：内容量、评论量。
- 柱体总高对应 `total_volume`。
- 峰值日期使用主题色强调，并标注峰值声量与峰值贡献率。
- 数据不足两个日期时退化为单日构成柱，不推断趋势。

### 话题驱动：横向排名图

- Y 轴：话题，最多展示前 10 项。
- 主长度：评论量，表示讨论规模。
- 辅助信息：内容量和累计互动量，以标签或次级标记呈现。
- 排序使用接口已有数据的确定性规则，不由 LLM 重排。
- 无话题数据时展示“暂无可识别话题”。

### 传播主体：作者贡献棒棒糖图

- Y 轴：作者，最多展示前 5 名。
- 主长度：累计互动量。
- 圆点大小：内容数。
- 作者类型作为辅助标签；缺失时不补造。
- 不使用自由力导向气泡，避免少量作者时布局松散或标签碰撞。

### 渠道效率：平台效率散点图

- X 轴：传播规模，优先使用平台明细已有的总声量字段。
- Y 轴：单内容互动量 `engagement_per_content`。
- 气泡大小：仅在平台明细存在稳定且同口径的第三指标时使用；否则保持统一大小。
- 平台名称直接标注，避免依赖图例识别。
- 单个平台时展示指标卡式散点状态，不制造横向比较。

## 移除与降级内容

- 删除市场图表模式中的“用户反馈构成”。
- 情感比例不再成为市场部独立图表。
- 产品点反馈由产品部报告承接。
- 购买信号由销售部报告承接。
- `feedback_quality` 仅可在复盘文案中作为传播承接质量的辅助证据，不形成独立章节。
- 地区响应暂不进入固定故事线，避免把评论位置误读为真实用户所在地或内容发布地。

## 数据与生成边界

市场报告 Prompt 固定输出标题、摘要、四章文案、复盘收束和数据说明。所有指标引用必须来自市场上下文中的已知路径。系统继续负责上下文裁剪、图表数据标准化和前端渲染。

LLM 不得：

- 生成或选择图表类型；
- 修改、计算或重新排序图表数据；
- 推断缺失趋势、传播归因或外部市场事实；
- 输出产品建议、销售建议或营销动作建议。

## 兼容与错误处理

- 兼容历史报告：历史报告仍按保存时的结构查看，不在读取时重写。
- 新报告缺少某章节数据时保留章节位置并显示空状态，其他章节继续展示。
- Prompt 输出缺字段或格式非法时，沿用现有规则化兜底，但兜底文案只引用确定性汇总字段。
- 图表数据出现非法数值时由现有标准化层过滤，不传给渲染组件。

## 验收标准

1. 市场部摘要模式形成完整的传播复盘故事，不再与图表说明逐句重复。
2. 图表模式固定展示传播态势、话题驱动、传播主体和渠道效率四张图。
3. “用户反馈构成”不再出现在市场部报告中。
4. 所有标题、结论、指标和图表数据均可追溯到现有市场看板上下文。
5. 缺失话题、作者、平台或趋势数据时，单个章节正确降级且报告可继续查看。
6. 不影响产品部、销售部、事件综合报告及历史市场报告。
7. 后端相关测试、前端类型检查和生产构建通过。

## 明确不在本轮范围内

- 新增后端业务指标或数据库字段；
- 实时监测与告警模式；
- 地区传播地图；
- 由 LLM 动态选择图表；
- 自动生成营销建议；
- 修改产品部和销售部的故事线。
