# 产品部 AI 报告摘要故事线设计

## 目标

把产品部 AI 报告的摘要模式从“重复图表 insight 的卡片列表”升级为业务人员可在两分钟内读完的事件故事。摘要负责解释事件主线，图表模式负责展示完整数据分布，两者不再承担相同职责。

本次只调整产品部报告。市场部、销售部报告保持现状，后续分别设计业务故事线后接入同一套摘要框架与颜色体系。

## 内容原则

- 结论先行，按业务问题组织内容，不按图表顺序复述。
- 只做事实归纳和证据推论，不输出行动建议。
- 数字必须来自现有接口数据，LLM 不自行计算或抄写最终展示值。
- 用户原话必须引用上下文中真实存在的评论 ID。
- 缺少数据时隐藏对应指标或证据，不补造内容。

## 固定故事线

### 顶部：一句话事件结论

展示：

- 事件名称与“事件综合摘要”标签。
- 一句话总判断 `headline`。
- 两至三句故事导语 `lead`。
- 三个由系统从现有数据中固定选择的关键指标胶囊；指标值由前端从真实报告数据读取。

### 第一章：用户在关注什么

组合产品关注点、提及占比、评论量和讨论集中度，回答用户讨论焦点及其集中程度。

### 第二章：用户如何评价

组合正向、中性、负向反馈与惊喜点、机会点、风险点，回答用户态度及主要矛盾。三类判断仅作为事实标签，不生成建议。

### 第三章：用户在和谁比较

组合 PKO 主要竞品、主要维度及优势、劣势、中性结果，回答用户比较对象与比较结论。

### 第四章：证据如何支撑

使用最多两条真实代表性评论完成故事收束。每条证据保留评论 ID 的可追溯关系，不显示后端内部字段路径。

## Agent 输出契约

在产品报告 `report_narrative` 中新增 `storyline`：

```json
{
  "storyline": {
    "headline": "一句话事件判断",
    "lead": "两至三句故事导语",
    "chapters": [
      {
        "chapter_id": "focus",
        "title": "用户在关注什么",
        "conclusion": "本章核心判断",
        "body": "两至三句解释",
        "metric_refs": ["product_focus.aspects"],
        "evidence_refs": []
      }
    ]
  }
}
```

约束：

- `chapters` 固定按 `focus`、`attitude`、`comparison`、`evidence` 顺序输出四章。
- `metric_refs` 只能使用提示词中允许的现有数据路径。
- `evidence_refs` 只能引用上下文中存在的评论 ID，每章最多两条。
- LLM 负责判断与叙事，不在正文中承担最终数字计算。
- 原有 `section_insights` 保留，继续服务图表模式，避免摘要与图表共用同一段文字。

## 数据流

1. 后端继续使用现有产品报告上下文和指标计算结果。
2. 产品报告提示词要求 LLM 生成独立 `storyline`。
3. 后端校验固定章节、字段类型、指标路径和证据 ID；无效引用被过滤。
4. 前端根据 `metric_refs` 从结构化报告数据中解析真实指标。
5. 前端将章节文字、真实指标和真实评论组合成故事页面。

## 视觉设计

视觉参考主页 AI 对话框，但只保留其克制的 AI 氛围：

- 只使用系统主题青绿色及其低饱和浅色、透明度变化。
- 顶部结论卡使用极浅主题色渐变、轻量光晕、白色内容面。
- 页面主体保持白底、深色正文和统一边框。
- 惊喜、机会、风险不再分别使用绿、蓝、红大色块；统一使用主题色标签，通过文字和明度区分。
- 禁止引入多色章节卡、彩虹渐变和大面积高饱和背景。

下方四章采用纵向故事线：

- 左侧显示 `01` 至 `04` 序号与细连接线。
- 中间展示章节标题、结论和正文。
- 右侧展示关键指标或证据卡。
- 窄屏改为单列，序号位于章节标题上方。
- 不展示图表模板编号，不复制完整图表。

## 兼容与降级

- 新生成的产品报告使用 `storyline`。
- 历史报告没有 `storyline` 时继续展示当前摘要卡，不影响历史资产查看。
- `storyline` 结构不完整时回退旧摘要；图表模式和数据依据模式仍可正常使用。
- 指标引用失效时隐藏对应指标；证据引用失效时隐藏证据卡。
- 所有章节均无可展示内容时回退旧摘要，不渲染空故事框架。

## 验收标准

- 摘要顶部存在一句话结论卡和故事导语。
- 下方按四章纵向故事线展开。
- 摘要正文不再逐条复制五张图表的 insight。
- 图表模式继续使用原 `section_insights`，职责不变。
- 所有展示数字可追溯到结构化报告真实数据。
- 所有代表性评论可追溯到真实评论 ID。
- 页面仅使用一套主题色体系，没有多色块堆叠。
- 不输出行动建议，不改变既有指标口径。
- 历史产品报告、市场部报告和销售部报告保持兼容。
- 产品报告专项测试、全量测试、前端类型检查和生产构建通过。

## 后续复用边界

- 共享：顶部结论卡、纵向故事章节、指标胶囊、证据卡、空态规则和单一主题色体系。
- 不共享：章节名称、章节业务含义、指标选择规则和 Agent 提示词内容。
- 市场部后续围绕传播节奏、话题、平台与反馈设计独立故事线。
- 销售部后续围绕线索漏斗、购买信号、用户意图与渠道设计独立故事线。
- 三部门接入时复用 `report-summary-visual-system.md`，不复制产品部样式代码。
